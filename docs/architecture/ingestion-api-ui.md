# Ingestion, API and UI design
Issues #7, #8. Proposed.

## Pipeline
1. **Upload:** stream the authenticated upload into quarantine, validate declared size and detected magic bytes, generate an opaque asset ID, calculate SHA-256 and write job intent in the same transaction.
2. **Scan:** ClamAV, fail-closed. Infected or unsupported files are rejected; an unavailable scanner leaves the asset quarantined for retry.
3. **Extract:** EXIF/IPTC/XMP with ExifTool, after the scan.
4. **Render:** NetVips (libvips) creates a JPEG/WebP thumbnail (320 px longest edge) and preview (1600 px), with no upscaling.

Initial formats are JPEG, PNG and WebP. Proposed limits: 100 MiB per file and 50 megapixels decoded. Malformed and unsupported files are rejected and the original is preserved.

**Isolation:** the parser subprocess runs non-root in an isolated temporary directory with network denied, a 60 s timeout and a 512 MiB memory limit (to be validated). Filenames are never interpreted as shell commands.

**Jobs:** the .NET worker claims jobs from the PostgreSQL queue ([ADR 0002](../adr/0002-job-backend.md)).
- Transient failures retry 3 times with exponential backoff; permanent failures do not retry.
- The deterministic job key is asset ID + pipeline version + stage.
- Processing status and a structured error category are persisted; only an authorized editor/admin can retry.
- Dead-lettered jobs are visible to operators; outbox re-dispatch and reconciliation recover restarts. No raw metadata secrets are logged.

**PoC:** valid, corrupt, oversize, scanner-unavailable and EICAR test files. Verify no premature download, checksums, deterministic output and throughput against #12. Not executed yet.

## REST conventions
/api/v1, JSON UTF-8, with the OpenAPI document generated by ASP.NET Core and checked against the implementation in CI. The frontend's TypeScript client is generated from that document. RFC 9457 problem details without internal paths; 401 unauthenticated, 403 denied or 404 where existence is sensitive.

Cursor pagination defaults to 50, max 200, with allowlisted filter/sort. Idempotency-Key for uploads/commands with a scoped key + request fingerprint; mismatched replay returns 409. ETag/If-Match for metadata changes; a stale update returns 412.

Endpoints: /catalogs, /catalogs/{id}/categories, /assets (upload/list), /assets/{id}, /assets/{id}/metadata, /assets/{id}/content, /assets/{id}/renditions/{kind}, /assets/{id}/retry, /audit-events. Uploads and downloads stream; HTTP Range is supported for active authorized files; no public links. Resumable multipart is deferred unless #13 requires files over 100 MiB. Every route and range request enforces the same authorization. Sensitive content is sent with private/no-store caching; access is revoked on subsequent requests.

## UI
React/Vite SPA, TanStack Query server state, TanStack Table for lists, virtualized grid, detail/preview pane, upload progress, job status and retry, category tree and metadata form. Bulk selection scoped to current query; bulk editing deferred unless #13 selects it. Keyboard navigable grid/tree, labels, focus management, text alternatives, accessible error states; target WCAG 2.2 AA on critical flows. English UI first, translation keys prepared for German. Same-origin session cookie; no bearer token in localStorage; login/logout via API, handle 401/403 without data leak. Test with Playwright, axe-core plus manual keyboard review. Contract checks validate status codes, schema, pagination, ETag and access failures.
