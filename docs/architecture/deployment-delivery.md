# Deployment and engineering delivery
Issues #10, #11. Proposed reference deployment.

## Runtime
Docker Engine + Compose v2 on Linux, Caddy ingress only (80/443); private application/data networks. Services web, api, worker, postgres, valkey, clamav, caddy, Keycloak candidate; filesystem volume for managed originals/quarantine/renditions, optional S3-compatible service in test profile. Persistent postgres, asset store, Valkey queue persistence (reconstructible from outbox), ClamAV signatures, identity data and Caddy certificates. Document volume ownership and backup coverage. Dev/test/prod profiles; no default credentials in production. Pin supported versions/digests after dependency check, multi-stage minimal images, non-root where supported, read-only root FS, drop capabilities, no-new-privileges, resource limits; parser sandbox no network (worker orchestrator retains service network). Compose healthchecks; readiness depends on DB and required services, worker liveness separate; structured redacted logs, queue age/failure, API latency/error metrics, disk alerts and OpenTelemetry traces. Reference host proposal 4 vCPU, 16 GiB RAM, 1 TB usable asset storage plus separate backup capacity; validate #12 workload. Assess amd64/arm64, Podman best-effort until tested, Docker Desktop optional per ADR 0003. Kubernetes deferred until multi-host HA or sustained scaling demands exceed Compose operating model.

## Backup/recovery
Proposed RPO 24h, RTO 4h on reference dataset. Quiesce asset writes/workers or establish consistent backup checkpoint; snapshot DB and asset originals, manifest of IDs/checksums, IdP/config/secrets via secure backup, encrypt and store off-host with retention and restore access control. Restore isolated instance, replay/reconcile pending jobs, verify counts, authorization, original hashes and previews; log duration and data-loss window. Rebuild renditions when needed. Preflight upgrades with schema compatibility, verified backup checkpoint, one-off migration container; roll back image only if schema compatible, otherwise forward fix or tested restore with explicit data-loss approval. Run failed migration/recovery drill. No restore or Compose PoC performed.

## Repo and CI
pnpm workspace: apps/web, apps/api, apps/worker; packages/contracts, packages/domain (framework-free), packages/config, packages/ui; docs/architecture, docs/adr, docs/diagrams, tests/e2e, poc/. Single lockfile; pin Node/pnpm and action commit SHAs; frozen install. Short-lived branches, PR references issues, conventional commits, CODEOWNERS roles pending actual owners; one approving review before merge. Group related issues in a PR, use per-issue acceptance evidence and keep unresolved items open. No auto-close for partial design.
PR gates: docs/ADR metadata/link checks, lint, strict TypeScript, unit/integration tests with PostgreSQL/Valkey test containers, OpenAPI contract diff, build, coverage gate #12, dependency/license scan, SBOM and container scan. E2E critical paths, accessibility and security tests on release candidate; report artifacts. Least-privilege CI permissions, no secrets in untrusted PR jobs, protected release publishing. SemVer, immutable image tags and digests, OCI labels, signed release artifacts where supported. No application or CI implementation in this design PR. Walking skeleton after #2 and #11 acceptance per #14.
