# ADR 0001: Core application stack

## Context and decision drivers
ZIRRUS needs a maintainable DAM with typed contracts, flexible metadata, durable asynchronous media processing, secure defaults and low operational burden. PostgreSQL was confirmed earlier. Before implementation, the product owner asked for an ASP.NET Core alternative to the TypeScript/Node.js backend to be evaluated ([backend reassessment](../architecture/backend-reassessment.md)).

## Considered options
- **A:** TypeScript / Node.js / NestJS backend, React frontend.
- **B:** C# / .NET 10 LTS / ASP.NET Core backend, React/TypeScript frontend.
- **C:** a comparative proof of concept in both stacks before deciding.

Python/FastAPI and Java/Spring Boot remain historical options only ([technology evaluation](../architecture/technology-stack.md)).

## Decision outcome
**Option B**, decided by the product owner on 2026-11-26 (REV-BE-01).

- **Backend:** C# on .NET 10 LTS, ASP.NET Core modular monolith (API) plus a separately deployable .NET worker.
- **Frontend:** React/Vite SPA in TypeScript, unchanged.
- **Database:** PostgreSQL, unchanged.
- **Contract:** REST with an OpenAPI document generated by the API and checked in CI; the frontend uses a TypeScript client generated from it.
- Python workers are allowed only where evidence justifies them. Option C was not chosen: both stacks are viable and a duplicate slice would mostly measure who built it.

## Consequences
- **Good:**
  - Authentication, cookies, antiforgery, policy authorization, DI, configuration, health checks and OpenAPI are first-party.
  - EF Core + Npgsql cover JSONB, full-text search and migrations (ADR 0005).
  - The worker can consume the PostgreSQL outbox directly, so Valkey is not needed (ADR 0002).
  - DocWizz models ASP.NET Core endpoints, authorization, DI and `DbContext` access, and its default C# layer rules match the planned project names.
- **Bad:**
  - Two toolchains (dotnet + pnpm) in the repo and CI.
  - Several popular .NET libraries are commercial or copyleft (ADR 0003).
  - .NET 10 support ends in November 2028, so the move to the next LTS must be planned.
- **Neutral:** media parsing stays in isolated processes whatever the runtime.

## Acceptance evidence
The product owner decision REV-BE-01 is the deciding evidence. This ADR takes effect when the pull request recording it merges with an approving review. Framework versions are pinned when the walking skeleton is created. The validation spike in the [backend reassessment](../architecture/backend-reassessment.md) gates ADRs 0002 and 0005, not this decision.
